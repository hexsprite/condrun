# condrun v0.1.0 — Vertical Slice

## Intent

condrun gates command execution on system state predicates and kills the child process if predicates flip mid-run. v0.1.0 ships the vertical slice: two metered-connection predicates (`--reject-expensive` and `--reject-low-data`) fully wired end-to-end on macOS via Network.framework's `NWPathMonitor`, with the trait seams, supervisor engine, and test infrastructure that the full predicate catalog builds on.

The use case: bulk uploads (restic, rsync, borg) should NOT run when macOS considers the connection expensive (Personal Hotspot, cellular tether) or constrained (Low Data Mode). SSID matching is deferred to v0.1.x — the metered/constrained signal is the right primitive for "don't burn the user's bandwidth."

Success: `condrun run --reject-expensive --reject-low-data -- restic backup ~/work` runs restic only when the system reports an unmetered, unconstrained connection. Kills it cleanly (process group SIGTERM + grace + SIGKILL) if the user tethers to their phone mid-backup, and exits with a meaningful code that cron/launchd can act on.

## User Workflows

### 1. Gate a backup on unmetered, unconstrained connection

```bash
condrun run --reject-expensive --reject-low-data -- restic backup -r s3:bucket ~/work
```

1. condrun evaluates: is current network expensive (cellular/hotspot)? Is Low Data Mode on?
2. If either fails: exit 0 silently (cron-friendly). With `--strict`: exit 1 + log reason.
3. If both pass: spawn `restic backup`, inherit its stdout/stderr.
4. Every `--poll` interval (default 30s), re-check both predicates.
5. If user tethers to phone mid-backup → `isExpensive` flips true → start `--debounce` timer (default 0 = immediate).
6. If debounce expires: SIGTERM to restic's process group, wait `--grace` (default 30s), SIGKILL if still alive. Exit 3.
7. If restic finishes naturally: exit 0 (success) or exit 2 (restic failed, original code logged).

### 2. Quick check in a shell script

```bash
if condrun check --reject-expensive; then
  rsync -av ~/photos backup-host:photos/
fi
```

1. condrun evaluates predicate once.
2. Exit 0 = pass. Exit 1 = fail (always strict in check mode).
3. `--explain` flag prints which predicate failed and why.

### 3. Debug "why didn't my backup run?"

```bash
condrun check --reject-expensive --reject-low-data --explain
```

Output: `FAIL: reject-expensive — current connection is expensive (Personal Hotspot or cellular)`

## Constraints

- **Language**: Rust 2024 edition, async via tokio multi-thread runtime
- **Platform**: macOS only for v0.1.0 (aarch64-apple-darwin primary, x86_64-apple-darwin secondary)
- **Network introspection**: Native `NWPathMonitor` via Network.framework, accessed through objc2 FFI. No sudo. No Location Services. No special entitlements. Reads `path.isExpensive` (cellular/Personal-Hotspot) and `path.isConstrained` (Low Data Mode).
- **Process management**: Process group isolation via `setsid`. Signal escalation via `killpg`.
- **No external runtime deps**: No databases, no network services, no config servers. Binary + optional YAML config file.
- **Test runner**: `cargo nextest` for parallel test execution. Integration tests require `--features test-fixture`.
- **Cargo features**: `test-fixture` (gates `FixtureNetworkState` + `--state-source` flag for integration testing), `platform-tests` (gates opt-in real macOS smoke tests in `src/state/macos.rs`). Default features: none.
- **Unsigned binary**: v0.1.0 ships unsigned. No prompt during runtime — NWPathMonitor doesn't require any entitlement.

## Architecture

| Decision | Chosen | Rejected | Rationale |
|----------|--------|----------|-----------|
| Metered detection | `NWPathMonitor` (Network.framework) via objc2 | CoreWLAN+SSID matching, shell-out to `networksetup`, `sudo plutil` for low-data plist | NWPathMonitor exposes `isExpensive` (covers cellular + Personal Hotspot) and `isConstrained` (Low Data Mode) in one API. No sudo. No Location Services. No entitlements. Bypasses the entire SPEC §11 permission story. |
| Predicate primitive | Metered/constrained boolean | SSID allowlist | "Don't burn the user's bandwidth" is the actual goal. SSID is a proxy that breaks at coffee shops, friend's houses, hotel wifi. Metered status answers the real question. SSID matching deferred to v0.1.x for users who want it. |
| Signal scope | Process group (`setsid` + `killpg`) | Direct PID kill | restic/borg/rsync spawn worker subprocesses. PID-only kill leaves zombie workers consuming bandwidth. |
| Debounce semantics | Wall-clock duration | Consecutive failed polls | Wall-clock is intuitive ("don't kill for 60s") and independent of poll interval. Consecutive polls couples two unrelated settings. |
| Integration test injection | JSON fixture file (`--state-source=file:path`) | Env vars, trait-level injection | JSON handles state sequences for mid-run predicate flip tests (scenarios 5-6). Env vars are flat and static. Trait injection doesn't test real binary wiring. |
| Module layout | `src/state/` (traits + platform impls) | `src/platform/` | SPEC §7.4 convention. Traits and their impls colocated. `state/` describes what it IS (system state), `platform/` describes where it runs. |
| Composition default | AND (all predicates must pass) | OR as default | AND is the safe default — accidentally running on the wrong network is worse than accidentally not running. OR is opt-in via `--any`. |
| Signal handling seam | `Signals` trait (RealSignals + FakeSignals) | Direct `tokio::signal::unix` calls | `tokio::signal` registers OS handlers globally; no injection seam for tests. Trait mirrors NetworkState/Spawner pattern. Tests use FakeSignals.inject(). |
| Time control | `tokio::time::Instant` directly + `pause()/advance()` in tests | Custom `Clock` trait per SPEC §7.1 | tokio's test-util provides deterministic time without an extra trait. SPEC's Clock trait is unnecessary plumbing. |
| Fixture exposure | Cargo feature `test-fixture` gates FixtureNetworkState + `--state-source` | `#[cfg(test)]`, separate test binary | `#[cfg(test)]` only applies to unit tests, not integration test binary subprocess. Feature flag keeps fixture out of production builds while letting integration tests build with it. |

## Testing Strategy

### Levels In Scope

- **Unit tests (~70%)**: Each predicate against `FakeNetworkState`. Supervisor scenarios against fakes + `tokio::time::pause()`. PredicateSet composition. Config parsing.
- **Integration tests (~25%)**: `assert_cmd` invokes real `condrun` binary with `--state-source=file:fixture.json`. Exercises CLI parsing + dispatch + supervisor wiring without real network calls.
- **Platform smoke (~5%, opt-in)**: `cargo nextest run --features platform-tests` exercises `MacOsNetworkState` against the actual host. Not counted toward coverage gate.

### Harness Conventions

- **Test runner**: `cargo nextest run` (parallel execution, JUnit XML output for CI)
- **Async test setup**: `#[tokio::test]` with `tokio::time::pause()` for deterministic time control. All supervisor + watcher tests use paused time + `tokio::time::advance()`.
- **Test doubles**: `FakeNetworkState` (interior mutability via `Arc<Mutex<_>>`, `set_expensive()`, `set_low_data()`), `FakeSpawner` (records spawn calls), `FakeChildHandle` (scriptable exit code + timing, records signals received), `FakeSignals` (programmatic signal injection for SIGINT/SIGTERM tests).
- **Fixture directory**: `tests/fixtures/` for JSON state fixtures used by integration tests.
- **Fixture schema**: `StateFixture` serde struct — either a static `NetworkSnapshot` or a `Vec<TimedSnapshot>` with `at: Duration` fields for state transitions.
- **Integration test pattern**: create `tempfile` with JSON fixture → invoke `condrun --state-source=file:<path> ...` via `assert_cmd::Command` → assert exit code + stderr content.
- **Coverage**: `cargo llvm-cov` targeting >90% on library code. Platform impls excluded.
- **No real network/process spawns in unit tests.** No flaky time-based tests — all use paused tokio time.

### macOS Platform + Predicates

#### NWPathMonitor reader via objc2/Network.framework

`src/state/macos.rs`, gated behind `#[cfg(target_os = "macos")]`. `MacOsNetworkState` struct implementing `NetworkState`. Wraps `nw_path_monitor_t` from Network.framework. Network.framework is C-based, not Objective-C — bind via `extern "C"` declarations and `#[link(name = "Network", kind = "framework")]`. Required functions: `nw_path_monitor_create`, `nw_path_monitor_set_update_handler`, `nw_path_monitor_set_queue` (use a dedicated dispatch queue), `nw_path_monitor_start`, `nw_path_is_expensive`, `nw_path_is_constrained`, `dispatch_queue_create`. Required types: `nw_path_t` (opaque), `nw_path_monitor_t` (opaque), `dispatch_queue_t` (opaque).

Lifecycle: `MacOsNetworkState::new()` creates an `Arc<Mutex<NwPathSnapshot>>` (where `NwPathSnapshot { expensive: bool, low_data: bool }` mirrors the trait surface), creates an `nw_path_monitor_t` with an update handler block that captures the Arc and writes the latest path's `is_expensive`/`is_constrained` into the snapshot, starts the monitor on a dedicated dispatch queue, and stores both the monitor handle and the snapshot Arc in the struct. `is_expensive()`/`is_low_data_mode()` lock the Mutex and return the cached value. The monitor runs in the background and updates the snapshot whenever the system path changes; supervisor's polling loop reads the latest cached value.

**Why polling over events**: NWPathMonitor naturally emits events to the update handler. v0.1 still uses polling (supervisor reads the cached snapshot at `--poll` interval) because: (a) the supervisor architecture is generic across platforms and predicates, polling is the lowest-common-denominator interface; (b) event delivery from NWPathMonitor still flows into the snapshot continuously, so polling observes transitions within `--poll` of when they happen; (c) v0.2 can hook the update handler directly into the supervisor's signal channel for instant detection without changing the trait surface. The cached-snapshot pattern is the bridge.

**Block lifecycle**: Use `block2::RcBlock` (NOT `StackBlock`) for the update handler, since `nw_path_monitor_set_update_handler` retains the block via `Block_copy` and invokes it many times. A stack block would dangle. Add `objc2`, `objc2-foundation`, and `block2` to `[target.'cfg(target_os = "macos")'.dependencies]`.

**NW object retain/release**: NW objects (`nw_path_monitor_t`, `nw_path_t`) and dispatch objects (`dispatch_queue_t`) are reference-counted opaque types. In Rust extern "C" FFI (no ARC), Drop must explicitly call `nw_release` on the monitor and `dispatch_release` on the queue. Required additional FFI declarations: `nw_release`, `dispatch_release`. (Modern macOS supports OS_OBJECT autorelease for dispatch objects in Obj-C contexts, but raw extern "C" Rust does NOT participate — manual release is required.) `Drop` for `MacOsNetworkState` performs: `nw_path_monitor_cancel(monitor)` → `nw_release(monitor)` → `dispatch_release(queue)`. Order matters: cancel before release so callbacks stop firing before the monitor is freed.

**Drop/cancel race**: `nw_path_monitor_cancel` is asynchronous — pending blocks may still execute on the dispatch queue after `cancel` returns. Memory safety is preserved because the update handler captures `Arc<Mutex<NwPathSnapshot>>` (not `&MacOsNetworkState`), so the snapshot lives until the last block reference drops. The `MacOsNetworkState` struct can be dropped while in-flight blocks finish writing to the now-orphaned Arc — those writes are wasted but harmless. Document this explicitly so a reviewer doesn't assume callbacks halt synchronously on Drop.

**Acceptance:**
- `MacOsNetworkState::new()` succeeds without errors on macOS 14+
- `is_expensive()` returns `true` when the active connection is Personal Hotspot or cellular
- `is_expensive()` returns `false` when on regular wifi or wired ethernet
- `is_low_data_mode()` returns `true` when Low Data Mode is enabled for the active interface
- `is_low_data_mode()` returns `false` when Low Data Mode is disabled

#### TokioSpawner + process group management

`src/process/tokio.rs`. `TokioSpawner` struct (unit struct, no config). Implements `Spawner`. `spawn()`: build `tokio::process::Command` from `CommandSpec`. Set `pre_exec` (unsafe) to call `nix::unistd::setsid()` — creates new session so child gets its own process group. Inherit stdin (null), stdout, stderr. Return `TokioChildHandle`. Requires `nix` crate's `process` feature in Cargo.toml in addition to `signal` (update the Cargo.toml change in Core types task: `nix = { version = "0.29", features = ["signal", "process"] }`). `TokioChildHandle` wraps `tokio::process::Child`. `wait()`: delegates to `Child::wait()`, returns `ExitStatus`. `terminate(grace)`: send `SIGTERM` to process group via `nix::sys::signal::killpg(Pid::from_raw(pid as i32), Signal::SIGTERM)`. After `setsid`, the child's process-group ID equals its PID, so `killpg` takes the positive PID directly — do NOT use the `kill(-pid, ...)` negative-PID convention (that's for raw `kill`, not `killpg`). Start grace timer. `tokio::select!` on child exit vs grace timeout. If grace expires and child still alive: `killpg(Pid::from_raw(pid as i32), Signal::SIGKILL)`. `signal(kind)`: maps `condrun::signal::SignalKind::Interrupt → Signal::SIGINT`, `Terminate → Signal::SIGTERM`. Sends to process group via `killpg(Pid::from_raw(pid as i32), ...)`. No grace, no escalation — raw forwarding. `pid()`: returns child PID from `Child::id()`.

**Acceptance:**
- Spawning `echo hello` produces stdout containing "hello"
- Spawning `sleep 999` then `terminate(grace=1s)` kills the process within ~1s
- Spawning `sh -c 'trap "" TERM; sleep 999'` (SIGTERM-resistant) then `terminate(grace=1s)` → SIGKILL after 1s, process dies
- Spawning `sh -c 'trap "echo got-int; exit 130" INT; sleep 999'` then `signal(Interrupt)` → child exits 130 (raw signal forwarding, no escalation)
- Child PID is in a different session ID than condrun's PID
- Spawning a nonexistent command returns an error (not panic)
- Child that exits 42 → `wait()` returns ExitStatus with code 42

### Supervisor Engine

The core orchestration: pre-flight gating, child lifecycle, state monitoring, and kill decisions.

**Inter-task contract**: The Supervisor struct signature (including all four fields: `predicate_set`, `spawner`, `state`, `signals`, `config` and the full `SupervisorConfig`) is established by the first task (Pre-flight + spawn + exit propagation) and DOES NOT change in subsequent tasks. Subsequent tasks (watcher, debounce, SIGINT forwarding) extend `Supervisor::run()` behavior internally — they do NOT modify the struct fields, the method signature, or any public API. This guarantees that tests written in earlier tasks remain valid as later tasks land. All four supervisor tasks compose into a single `Supervisor::run()` method that branches on `kill_on_change`, watches state, debounces flips, and races signal handling.

#### Supervisor watcher + kill-on-change

Extend `Supervisor::run()` for the `kill_on_change: true` path. After spawning child: start a poll loop. Each tick: `tokio::time::sleep(poll)` then re-evaluate `predicate_set` against current `state`. If `Fail`: call `child.terminate(grace)`. If child exits within grace: ok. If grace expires: SIGKILL (handled by `TokioChildHandle::terminate()`). Return exit code 3. If child exits naturally during the watch loop: return 0 or 2 based on exit code. Use `tokio::select!` to race child completion against the next poll tick. Requires: Supervisor pre-flight + spawn.

- Multiple state flips during one poll interval → only one terminate triggered
- Poll interval respected: with `--poll 5s`, state checked every 5s (not faster)

#### SIGINT/SIGTERM forwarding to child

Install signal handlers on the condrun process itself so that Ctrl+C (SIGINT) and SIGTERM are forwarded to the child process group for graceful shutdown. Without this, Ctrl+C kills condrun but orphans the child (restic, rsync, etc.) — a real operational hazard. Implement `RealSignals` in `src/signal/real.rs` — internally calls `tokio::signal::unix::signal(tokio::signal::unix::SignalKind::interrupt())` and `tokio::signal::unix::signal(tokio::signal::unix::SignalKind::terminate())` (Tokio's enum, fully qualified to disambiguate from condrun's own `condrun::signal::SignalKind`). The `Signals::next()` method `tokio::select!`s across both Tokio streams and returns condrun's `SignalKind::Interrupt` or `SignalKind::Terminate`. The plan-level `SignalKind` enum (defined in Core types task) is what flows through condrun's API; Tokio's enum is an implementation detail of `RealSignals` only. Supervisor's `signals` field (already locked as `Box<dyn Signals>` in the pre-flight task — DO NOT change the struct signature) is consumed by this task's run-loop changes only. When `self.signals.next()` resolves with a `SignalKind`: forward to the child via the new `ChildHandle::signal(kind: SignalKind)` method (added to the trait in this task — see Trait change note below), then wait for the child to exit (no automatic SIGKILL escalation here; the existing `terminate(grace)` path handles that on predicate-flip kills). Wire into the supervisor's `tokio::select!` loop alongside the poll tick and child completion. **Pre-flight signal racing**: pre-flight evaluation also races against `self.signals.next()` via `tokio::select!`. If a signal arrives during predicate evaluation (before any child is spawned), the supervisor exits 0 immediately without spawning. This requires the pre-flight phase to use `tokio::select!` rather than a plain `await` on `predicate_set.evaluate()` — modify the pre-flight task's run() implementation (within this SIGINT task, since the supervisor struct signature is locked) to wrap evaluation in select! against signals. **Uses existing `ChildHandle::signal(SignalKind)` method** (defined in Core types task, implemented in TokioSpawner task and Test doubles task). The `signal()` method sends the corresponding Unix signal to the process group via `killpg` — raw forwarding without grace escalation. Existing `terminate(grace)` continues to mean "SIGTERM with grace then SIGKILL" — that's the kill-on-change path. The `FakeChildHandle::last_signal()` accessor (also from Test doubles task) lets tests verify SIGINT vs SIGTERM was forwarded. Requires: Supervisor watcher + kill-on-change, Test doubles (FakeSignals, FakeChildHandle).

**Acceptance:**
- Ctrl+C to condrun → child process group receives SIGINT
- SIGTERM to condrun → child process group receives SIGTERM
- After forwarding, condrun waits for child to exit and maps its exit code per existing rules: child exits 0 → return 0; child exits non-zero (including 130 from SIGINT) → return 2 (logs original code). NO new exit code introduced for the signal-forwarding path.
- Signal-forwarding path does NOT escalate to SIGKILL. Raw forwarding only. If child ignores the forwarded signal, condrun waits for the child to exit naturally (or until receiving another signal). Predicate-flip kill path is separate and handles its own SIGTERM → grace → SIGKILL escalation.
- If no child is running (pre-flight phase still evaluating), signal received during pre-flight makes condrun exit 0 (signal interrupts work cleanly, as if pre-flight returned a non-strict fail)

## Known Limitations (v0.1.0)

- **Suspend/resume**: v0.1 kills on predicate flip. SIGSTOP/SIGCONT for pause-and-resume deferred to v0.1.x.
- **Event-driven watching**: v0.1 polls at `--poll` interval. Hooking `NWPathMonitor` updates directly for instant detection deferred to v0.2.
- **Limited predicates**: Only `--reject-expensive` and `--reject-low-data` in v0.1.0. Full catalog (SSID matching, AC power, interface type) ships in v0.1.x.
- **macOS only**: Linux NetworkManager support deferred to v0.1.x.
